# 节点提示词面板模型配置缓存

## 问题与目标

当前 `useAgentCanvasProviderModels` 在取消选中节点时清空模型列表和默认配置。
重开面板会再次请求 `/api/v1/models?node_type=...&include_unavailable=true`
和 `/api/v1/model-defaults`，没有跨面板生命周期的缓存；两份响应通过
`Promise.allSettled` 一起更新，慢请求会延后其他已返回数据的展示。

目标：同一页面会话内，关闭/重开、同类型切换及切回已加载的类型时直接复用
模型数据，不出现无必要的 Loading；配置更改后可靠失效，不永远使用旧配置。
提示词正文、保存参数、参考资产和 Workflow/Runtime 合同保持不变。

## 方案

1. 使用小型、专用的内存资源缓存，不增加第三方依赖，不持久化到浏览器存储。
   模型目录按后端原有查询 `node_type` 分键（最多五种），安装级默认配置全局一份。
   不按 node ID 缓存，不在前端推断兼容性，不缓存凭据或 API Key。
2. 每个资源复用未完成的 Promise，多个消费者、快速重开、React Strict Mode
   不重复请求。关闭面板只取消订阅，不清空缓存，不取消其他消费者使用的请求。
3. Hook 通过 `useSyncExternalStore` 同步读取对应类型的稳定快照。
   目录和默认配置分别发布结果；首次确实缺少必要数据时仍显示加载状态。
   缓存命中首次渲染即有数据，不先清空再用 effect 填回；切换类型不显示上一类型的模型。
4. 成功数据有效期设为 5 分钟。过期后在打开/切换节点时后台更新，保留已知数据；
   页面重新获得焦点时，对当前使用资源进行一次后台校验，以覆盖其他页面/外部配置改动。
   不新增轮询、定时刷新或无限重试。无使用者时不主动请求；失败后重开或再次聚焦可重试。
5. 在现有 API 客户端的成功写操作处发布不含敏感信息的配置失效通知：

   - 保存/清除凭据（含 base URL）、测试凭据、同步模型：失效目录和默认配置。
   - 保存默认模型：只失效默认配置。
   - 写失败不失效。只修改通知接入，不改变请求体、返回值及业务行为。

   已知配置变更采用清空对应数据的硬失效，防止继续选择已撤销的配置；
   其他类型标记过期后按需获取，当前订阅资源立即重新加载。
6. 每个请求绑定 generation；失效前的迟到响应不能覆盖新配置。
   后台刷新失败保留最近成功数据并显示错误；没有成功数据时保留现有错误提示。
   不自动更换模型/Provider，不改变后端执行前校验。

## 展示与请求验收

| 场景 | 预期 |
| --- | --- |
| 首次打开视频节点 | 目录、默认配置各 1 次请求；初次缺数据时 Loading |
| 关闭后重开同一节点 | 有效缓存直接展示，0 次新请求 |
| 直接切换另一个视频节点 | 0 次新请求；节点自身参数仍独立 |
| 视频 → 图片 → 视频 | 图片目录首次 1 次；默认配置共用，切回视频 0 次 |
| 请求未结束时关闭再开/多个消费者 | 每个资源只 1 次在途请求 |
| 缓存过期后打开 | 保留数据、后台更新，不重新闪 Loading |
| 保存默认模型 | 默认配置重新加载，模型目录不重复加载 |
| 修改凭据/同步模型 | 当前配置失效重载；旧请求不允许回写 |
| Editing 或 source-only 节点 | 不加载模型配置 |

## 边界

本缓存服务于当前浏览器页面实例；刷新页面后重新加载。
其他标签页/后端直接改配置，在当前页面重新聚焦时重新校验；持续前台停留
且不切换节点时不做轮询，因此不承诺外部改动在无交互情况下立即推送。
同页已知配置写入则立即失效。默认配置页不纳入读缓存，保留其原有加载流程。
