# AdCraft 深色主题设计规范

**日期：** 2026-07-27
**状态：** 已确认设计方向，尚未实施

## 1. 目标

在保留 AdCraft 当前浅色主题的基础上，增加一套以黑色系为主体的深色
主题，让用户可以根据使用环境和个人偏好切换界面风格。

深色主题采用已经确认的 A3「深夜墨黑」方向：以中性墨黑建立页面层级，
以鸢尾紫延续现有品牌识别，并让图片、视频、工作流节点和最终成片成为界面
中的视觉中心。

本次主题能力必须覆盖整个前端应用，而不是只改变页面背景。首页、项目、
资产库、回收站、API Space、工作流画布、节点、时间线、弹窗、菜单、表单
以及各种操作状态都应在同一主题下保持一致。

## 2. 设计原则

### 2.1 内容优先

深色背景应主动退后，不对图片和视频增加变暗、反色或降饱和滤镜。素材本身
保持原始亮度和色彩，承载素材的卡片、遮罩和控制区域再根据主题调整。

### 2.2 克制使用品牌色

黑灰色承担大约 80% 的界面面积，鸢尾紫控制在 10% 以内。紫色只用于主要
操作、当前选项、焦点、播放位置和少量品牌表达，不用于普通正文和大面积
卡片背景。

### 2.3 依靠层级而不是装饰

页面层级主要通过不同深度的黑灰表面、细边框和克制阴影建立。不使用纯黑、
纯白、大面积高饱和渐变或紫色光斑来制造深色氛围。

### 2.4 与浅色主题属于同一产品

主题切换只改变颜色、边框、阴影和与颜色直接相关的视觉状态，不改变布局、
字体体系、组件尺寸、交互流程、素材内容和信息层级。

## 3. 核心色板

### 3.1 基础与表面

| 语义角色 | 色值 | 主要用途 |
| --- | --- | --- |
| 页面背景 | `#08090D` | 页面底层、工作区外围、画布底色 |
| 导航背景 | `#0D0F14` | 顶部导航、左侧导航 |
| 卡片表面 | `#13161D` | 卡片、菜单、普通面板 |
| 抬升表面 | `#191D26` | 弹窗、输入区、浮动工具栏 |
| 输入框背景 | `#101218` | 输入框、选择器、技术信息区域 |
| 普通边框 | `#222733` | 卡片边界、区域分隔 |
| 强调边框 | `#333A49` | 悬停、聚焦和重要层级 |

不使用 `#000000` 作为大面积背景，也不使用 `#FFFFFF` 作为默认文字。这样
可以保留区域层次，同时降低长时间编辑时的视觉疲劳。

### 3.2 文字

| 语义角色 | 色值 | 主要用途 |
| --- | --- | --- |
| 主要文字 | `#F1F2F6` | 标题、正文、关键数据 |
| 次要文字 | `#9399A9` | 描述、辅助信息、占位文字 |
| 禁用文字 | `#666D7C` | 不可用控件和弱提示 |

默认正文需要满足至少 4.5:1 的对比度要求；大字号文字至少满足 3:1。不能
只通过降低透明度无限弱化次要文字。

### 3.3 品牌与交互

| 语义角色 | 色值 | 主要用途 |
| --- | --- | --- |
| 品牌紫 | `#9E8BEA` | 主按钮、选中状态、当前播放位置 |
| 品牌紫悬停 | `#AF9AF6` | 主按钮和可交互强调元素悬停 |
| 品牌紫弱背景 | `#241E39` | 当前导航、标签、选中区域 |
| 品牌紫焦点 | `#B6A4FF` | 键盘焦点轮廓 |

主按钮使用品牌紫背景和深色文字。次要按钮使用深灰表面，危险操作不能使用
品牌紫，应使用独立的错误状态色。

### 3.4 功能状态

| 状态 | 主色 | 建议弱背景 | 用途 |
| --- | --- | --- | --- |
| 成功 | `#5FCF96` | `#12291F` | 完成、在线、已保存 |
| 警告 | `#E4BC62` | `#2B2415` | 待检查、配置不完整 |
| 错误 | `#EB788C` | `#2C171C` | 失败、删除、阻断问题 |
| 信息 | `#7F9FE8` | `#17213A` | 普通提示、进行中状态 |

状态信息必须同时包含文字或图标，不能只依赖颜色表达。

## 4. 主题切换交互

主题切换按钮放在顶部导航右侧操作区，位于教程入口和账户按钮附近。按钮
使用太阳和月亮图标，不增加占用空间较大的文字按钮；通过悬停提示和动态
无障碍名称说明当前操作，例如“切换到深色主题”。

首个版本只有“浅色”和“深色”两种显式状态，不提供“跟随系统”的第三个
选项。第一次访问继续使用当前浅色主题，用户主动切换后，将选择保存在当前
浏览器的本地存储中。

主题偏好不写入后端、不与 API Key 或项目数据绑定，也不在不同设备间同步。
本地存储不可用时，当前页面仍可切换主题，但刷新后回到浅色主题。

页面在 React 渲染前读取本地主题偏好并设置根节点主题属性，避免页面先显示
浅色再闪烁为深色。切换过程中可以使用短暂的颜色过渡，但必须遵守用户的
“减少动态效果”系统设置。

## 5. 前端主题架构

根页面通过统一属性表达当前主题，例如 `data-theme="light"` 和
`data-theme="dark"`。组件不直接判断当前主题，也不在组件内部维护两套
颜色逻辑。

全局样式需要建立语义化颜色变量，至少覆盖以下类别：

- 页面、导航、普通面板、抬升面板和输入区域；
- 主要、次要、禁用和反色文字；
- 普通、强调和焦点边框；
- 品牌主色、弱背景和悬停状态；
- 成功、警告、错误和信息状态；
- 普通阴影、浮层阴影和遮罩。

当前 `apps/web/src/styles.css` 中存在较多直接写死的白色、浅色透明背景和
阴影。实施时需要把参与主题切换的颜色逐步映射到语义变量，不能只覆盖
现有少量根变量，也不能使用全局反色滤镜。

## 6. 页面和组件映射

### 6.1 应用外壳

页面最底层使用页面背景色。顶部导航和左侧导航使用导航背景色，并通过边框
与工作区分隔。当前导航项使用品牌紫弱背景和品牌紫图标。

### 6.2 首页与项目页面

首页保留现有字体和内容结构。深色主题不继续依赖浅色背景图的亮部作为页面
底色，应改用稳定的墨黑背景和克制纹理。项目卡片使用卡片表面色，预览图片
保持原色，文字遮罩需要保证标题在不同图片上都可读。

### 6.3 资产库

推荐资产、我的资产和资产查看器统一使用深色外壳。图片和视频预览不处理
原始颜色；选择边框、翻页控制和关闭按钮使用深色半透明表面，确保在明亮
素材上仍然清晰。

### 6.4 API Space

模型配置区域使用普通卡片表面，输入框使用专用输入背景。API Key、模型
标识等技术信息继续使用现有等宽字体。保存成功、测试失败和配置不完整必须
使用对应状态色与明确文字。

### 6.5 工作流和时间线

工作流画布使用页面背景色，节点使用卡片表面色，节点内部控制区域使用抬升
表面色。只有当前节点、连接端口和有效连接使用品牌紫，普通节点不能都带有
紫色外框。

时间线轨道保持黑灰层级，播放头、当前片段和当前操作使用品牌紫。音频、
视频、角色和场景可以保留各自的类别识别色，但需要降低背景饱和度，避免
与状态色和品牌紫竞争。

### 6.6 弹窗和浮层

弹窗、下拉菜单、账户菜单和浮动工具栏使用抬升表面色与更明确的边框、阴影。
遮罩使用中性黑色透明层，不使用紫色遮罩。浮层内容必须在深色和浅色主题下
保持相同的尺寸与定位。

## 7. 非目标

- 不重新设计页面布局、卡片结构或导航方式。
- 不更换已经确定的 Manrope、Instrument Serif 和 JetBrains Mono 字体体系。
- 不修改后端接口、数据库或用户模型。
- 不增加主题跟随系统、云端同步或定时切换。
- 不对用户上传或生成的图片、视频和音频封面做颜色处理。
- 不在本次工作中顺带重构与颜色主题无关的前端功能。

## 8. 异常和降级处理

- 本地主题偏好缺失、无效或无法解析时，使用浅色主题。
- 本地存储写入失败时，保持当前页面选择，不阻断其他功能。
- 图标或局部样式加载失败时，文字和操作仍需保持可见、可用。
- 第三方画布和时间线控件无法完全继承主题变量时，应为其公开的类名或主题
  接口提供显式映射，不能通过全局滤镜处理。

## 9. 验证和验收

### 9.1 自动验证

- 验证默认主题、保存的深色主题和无效存储值的初始化结果。
- 验证切换按钮能够更新根节点主题、按钮图标和无障碍名称。
- 验证本地存储失败不会导致页面崩溃。
- 增加主题样式契约检查，确保核心语义变量在浅色和深色主题中都有定义。
- 运行现有前端测试、React 规则检查和生产构建。

### 9.2 视觉验收

在桌面和移动端检查首页、项目、资产库、API Space 和工作流，至少覆盖：

- 默认、悬停、键盘聚焦、选中、禁用和加载状态；
- 成功、警告、错误和信息提示；
- 弹窗、菜单、素材查看器和媒体控制；
- 工作流节点、连线、画布、时间线和最终视频预览；
- 页面首次加载与主题切换过程中没有明显颜色闪烁；
- 图片和视频颜色未被主题样式改变；
- 文字、图标和边框在两种主题中均有足够对比度；
- 移动端没有因主题按钮或文字变化造成溢出、重叠和布局跳动。

## 10. 完成标准

当用户能够在任意页面通过顶部按钮切换浅色和 A3「深夜墨黑」主题，刷新后
仍保留选择，并且所有主要页面、工作流区域和浮层都不存在明显浅色残留、
不可读文字、素材偏色或交互状态缺失时，本功能才视为完成。
